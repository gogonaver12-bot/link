# Claude · Gemini 웹용 복사 프롬프트

웹 채팅에 아래 문구와 필요한 파일만 직접 복사한다. 비공개 저장소 링크만으로 접근할 수 있다고 가정하지 않는다. 키·쿠키·인증 정보는 첨부하지 않는다. 채팅과 Git은 자동 동기화되지 않는다.

## 프로젝트 시작 / 기획·프롬프트 작성

```text
이번 채팅에서는 아래 프로젝트 하나만 다룬다. 다른 프로젝트의 코드·설정·추정을 섞지 마라.
프로젝트명: [이름]
목표: [원하는 결과]
현재 확인된 사실: [현재 상태와 관련 코드/자료]
제약: Windows 11. 기존 프로젝트의 런타임과 구조를 우선. 요청 범위만 최소 수정. 유료 API는 호출하지 않음.

내 설명을 구현 가능한 작업 요청으로 정리하라. 모르는 사실을 만들어 내지 말고 결과에 영향을 주는 누락 정보만 한 번에 질문하라.
출력은 목표 / 범위 / 기대 동작 / 변경할 파일 후보 / 완료 기준 / 최소 검증 / 미확인 사항 순서로 짧게 작성하라.
마지막에 Codex에 그대로 복사할 실행 프롬프트 한 개를 작성하라.
파일을 보지 못했다면 경로와 코드 구조를 확정하지 말라. 파일 수정·실행·테스트를 실제로 하지 않았다면 완료했다고 말하지 말라.
```

## 조사 / 공식 출처 검증

```text
조사 주제: [AI 도구·오픈소스·영상 소재 또는 URL]
사용 목적: [프로젝트에서 활용할 목적]
검색 가능 여부를 먼저 확인하고, 가능하면 최근 7일의 유용한 후보 최대 3개를 조사하라.
홍보글을 공식 저장소·LICENSE·릴리스·설명서와 비교하라.
각 항목에 확인된 사실, 미확인 사항, 비용·로그인·설치 조건, 공식 링크, 확인일을 붙여라.
문서 확인과 직접 실행 확인을 구분하라. 검색할 수 없다면 최신 정보를 만들어 내지 말라.
설치·유료 API·계정 연결은 수행하지 말라. 마지막에 프로젝트 적용을 검토할 Codex 요청 프롬프트를 작성하라.
```

## Codex로 작업 전달

```text
프로젝트: [이름과 로컬 폴더]
GitHub: [이 프로젝트의 저장소 URL]
이번 목표: [한 가지 작업]
참고 분석: [Claude/Gemini 결과]

참고 분석을 미검증 제안으로 취급하고 실제 파일로 확인하라.
먼저 현재 폴더·브랜치·git status·AGENTS.md와 필요한 코드만 확인하라.
이 프로젝트의 codex worktree에서 최소 수정하고 관련 최소 검증만 실행하라.
다른 프로젝트, 다른 도구의 worktree, 전역 설정은 수정하지 말라.
미커밋 변경을 보존하고 force push·자동 병합·유료 API 호출은 하지 말라.
변경 파일, 원인과 수정, 실제 검증 결과, 남은 일을 짧게 보고하라.
```
