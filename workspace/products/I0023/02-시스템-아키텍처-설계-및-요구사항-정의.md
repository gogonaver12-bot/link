## 2. 시스템 아키텍처 설계 및 요구사항 정의

제조·물류 현장의 AI 도입에서 가장 치명적인 문제는 외부 API(Anthropic 등)의 예기치 않은 장애다. 현장 물류 시스템이나 실시간 관제 AI가 멈추면 곧바로 금전적 손실로 이어진다. 이를 막기 위해 본 장에서는 외부 클라우드 LLM과 사내 온프레미스 LLM을 실시간으로 연동하는 **FastAPI 기반 장애 자동 복구(Fallback) 게이트웨이**의 뼈대를 설계한다.

---

### 2.1 FastAPI 프록시 서버 전체 아키텍처

게이트웨이는 클라이언트(사내 서비스)와 LLM 제공자(Anthropic / Ollama) 사이에 위치한다. 핵심은 **"인터페이스 표준화"**다. 사내 애플리케이션은 Anthropic API 규격 그대로 요청을 보내고, 게이트웨이가 이를 받아 라우팅한다.

```
[사내 AI 서비스 / 물류 시스템]
           │ (Anthropic API 포맷 요청)
           ▼
┌────────────────────────────────────────┐
│     FastAPI Fallback Gateway           │
│  ┌──────────────────────────────────┐  │
│  │ 1. API 라우터 & 포맷 변환기        │  │
│  └──────────────────────────────────┘  │
│  ┌──────────────────────────────────┐  │
│  │ 2. 헬스체커 & 서킷 브레이커        │  │
│  └──────────────────────────────────┘  │
└───┬────────────────────────────────┬───┘
    │ (정상 시)                       │ (Anthropic 장애/타임아웃 시)
    ▼                                ▼
[Anthropic API 클라우드]       [온프레미스 GPU 서버]
                               (Ollama / Llama 3)
```

1. **API 라우터:** 사내 앱의 요청을 받아 1차로 클라우드(Anthropic)에 전달을 시도한다.
2. **상태 모니터링 및 서킷 브레이커:** Anthropic API가 타임아웃(예: 3초 이상)을 일으키거나 5xx 에러를 반환하면, 게이트웨이는 즉시 상태를 '장애'로 판정하고 트래픽을 온프레미스로 우회시킨다.
3. **포맷 변환기:** Anthropic의 응답 구조와 Ollama(Llama 3)의 응답 구조가 다르므로, 게이트웨이 내부에서 JSON 스키마를 상호 변환하여 사내 앱이 에러 없이 처리하도록 만든다.

---

### 2.2 온프레미스 서버 및 네트워크 환경 사전 체크리스트

사내 구축형(On-Premise) LLM 폴백 환경을 안정적으로 돌리기 위한 최소 요구사항이다. 프로젝트 착수 전 반드시 인프라 담당자와 아래 항목을 검증해야 한다.

| 구분 | 검증 항목 | 권장 사양 / 기준 | 확인 완료 |
| :--- | :--- | :--- | :--- |
| **GPU 서버** | VRAM 용량 | Llama 3 (8B 기준) 최소 16GB 이상 (RTX 4090 또는 A10G 권장) | [ ] |
| **소프트웨어** | 런타임 및 OS | Ubuntu 22.04 LTS, Docker, NVIDIA Container Toolkit 설치 | [ ] |

| **네트워크** | 내부 통신 지연 | 사내 앱 ➔ 게이트웨이 ➔ Ollama 서버 간 레이턴시 50ms 이하 | [ ] |

### 2.3 API 요청 라우팅 및 상태 모니터링 흐름 설계

장애 발생 시 서비스 중단 없이 0.5초 이내에 폴백이 일어나도록 설계된 라우팅 로직의 핵심 흐름이다.

1. **요청 유입:** 사내 시스템이 `POST /v1/messages`로 프롬프트를 전송한다.
2. **1차 시도 (Cloud):** FastAPI는 `httpx` 비동기 클라이언트를 이용해 Anthropic API 호출을 시도한다. 이때 `timeout=3.0`을 엄격하게 설정한다.
3. **예외 처리 (Fallback Trigger):**
   * 성공 시: Anthropic의 응답을 그대로(또는 변환하여) 클라이언트에 반환.
   * 실패 시(타임아웃, 5xx 에러, 연결 끊김): 로그를 기록하고 즉시 로컬 Ollama 엔드포인트(`http://localhost:11434/api/chat`)로 페이로드를 재전송한다.
4. **응답 정규화:** Ollama의 Llama 3 응답을 Anthropic 포맷으로 변환하여, 클라이언트는 백엔드가 바뀐 것을 인지하지 못하게 처리한다.

#### [복붙해서 쓰는 설정 템플릿: FastAPI 핵심 라우팅 로직 (Python)]

아래 코드는 실무에서 바로 테스트할 수 있는 라우팅 및 폴백 기본 구조다.

```python
import httpx
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI()

ANTHROPIC_API_URL = "https://api.anthropic.com/v1/messages"
OLLAMA_API_URL = "http://localhost:11434/api/chat"

class ChatRequest(BaseModel):
    prompt: str
    model: str = "claude-3-haiku-20240307"

@app.post("/v1/gateway/chat")
async def proxy_chat(request: ChatRequest):
    headers = {"x-api-key": "YOUR_ANTHROPIC_KEY", "anthropic-version": "2023-06-01"}
    
    # 1단계: Anthropic 클라우드 API 호출 시도 (타임아웃 3초)
    async with httpx.AsyncClient() as client:
        try:
            response = await client.post(
                ANTHROPIC_API_URL,
                json={"model": request.model, "max_tokens": 300, "messages": [{"role": "user", "content": request.prompt}]},
                headers=headers,
                timeout=3.0
            )
            if response.status_code == 200:
                return {"source": "anthropic_cloud", "data": response.json()}
        except (httpx.TimeoutException, httpx.RequestError):
            pass  # 타임아웃 또는 네트워크 오류 발생 시 하단 폴백 로직으로 이동

    # 2단계: 클라우드 장애 시 온프레미스 Ollama(Llama 3)로 자동 폴백
    async with httpx.AsyncClient() as client:
        try:
            ollama_payload = {
                "model": "llama3",
                "messages": [{"role": "user", "content": request.prompt}],
                "stream": False
            }
            ollama_response = await client.post(OLLAMA_API_URL, json=ollama_payload, timeout=10.0)
            
            if ollama_response.status_code != 200:
                raise HTTPException(status_code=500, gateway="All LLM backends failed")
                
            result = ollama_response.json()
            # Anthropic 포맷 형태로 응답 구조 맞춤 (정규화)
            return {
                "source": "onpremise_ollama_fallback",
                "data": {
                    "content": [{"text": result.get("message", {}).get("content", "")}]
                }
            }
        except Exception as e:
            raise HTTPException(status_code=500, detail=f"Critical: Both Cloud and On-Premise failed. Error: {str(e)}")
```

이 구조를 통해 제조·물류 현장은 클라우드 장애 리스크를 원천 차단하고, 사내 인프라를 활용한 고가용성(High Availability) AI 파이프라인을 확보하게 된다.
