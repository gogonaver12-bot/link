## 8. 실전 부하 테스트 및 컨설팅·구독 서비스 온보딩

구축이 완료되었다고 해서 시스템이 실전에서 완벽하게 동작하리라 기대하면 안 된다. 제조·물류 현장에서는 네트워크 지연, 갑작스러운 대량 호출, 외부 API 장애가 동시에 발생할 수 있다. 이번 장에서는 오픈소스 부하 테스트 도구인 Locust를 활용해 장애 복구(Fallback) 시나리오를 검증하고, 보안 감사 체크리스트와 안정적인 월 구독 유지보수(SLA) 계약 체결 프로세스를 다룬다.

---

### 1. Locust를 활용한 API 트래픽 부하 및 강제 장애 시뮬레이션

시스템이 Anthropic API에서 Ollama(Llama 3)로 끊김 없이 전환되는지 확인하려면 실제 트래픽 환경을 가정하고 테스트해야 한다. 아래 `locustfile.py` 스크립트를 사용해 가상 부하를 발생시키고, 테스트 도중 Anthropic API 엔드포인트를 강제로 차단(방화벽 규칙 변경 등)하여 폴백 작동 여부를 확인한다.

**실행 가능한 `locustfile.py` 템플릿:**

```python
import json
from locust import HttpUser, task, between

class LLMGatewayUser(HttpUser):
    wait_time = between(1, 3)

    @task(4)
    def send_normal_request(self):
        # 일반적인 LLM 게이트웨이 호출 테스트
        headers = {"Content-Type": "application/json"}
        payload = {
            "model": "claude-3-sonnet",
            "messages": [{"role": "user", "content": "제조 공정 데이터 분석 요약해줘."}],
            "max_tokens": 150
        }
        with self.client.post("/v1/chat/completions", json=payload, headers=headers, catch_response=True) as response:
            if response.status_code == 200:
                response.success()
            else:
                response.failure(f"Fail Code: {response.status_code}, Res: {response.text}")

    @task(1)
    def send_heavy_request(self):
        # 무거운 페이로드 테스트
        headers = {"Content-Type": "application/json"}
        payload = {
            "model": "claude-3-sonnet",
            "messages": [{"role": "user", "content": "전체 물류 창고 재고 최적화 알고리즘 작성..." * 10}],
            "max_tokens": 500
        }
        self.client.post("/v1/chat/completions", json=payload, headers=headers)
```

**부하 테스트 및 장애 시뮬레이션 단계:**
1. 터미널에서 `locust -f locustfile.py --host=http://<게이트웨이_내부_IP>:8000` 실행
2. 웹 브라우저 접속 (`http://localhost:8089`) 후 가상 사용자 50명, 초당 증가율 5명 설정하여 테스트 시작
3. 테스트 중 게이트웨이 서버 방화벽에서 Anthropic API 도메인으로 향하는 아웃바운드 트래픽 차단 (`iptables` 또는 네트워크 보안 그룹 수정)
4. Locust 대시보드와 게이트웨이 로그를 모니터링하여, 응답 지연 없이 Ollama(Llama 3)로 자동 폴백되는지 확인 (목표: 실패율 0%, 폴백 전환 시간 2초 이내)

### 2. 보안 감사(Security Audit) 및 로그 파이프라인 점검

제조·물류 대기업은 내부 데이터 유출에 민감하다. 온프레미스 LLM 게이트웨이 도입 시 반드시 거쳐야 할 보안 점검 항목이다.

**보안 감사 체크리스트:**
* [ ] **API Key 격리:** Anthropic API 키가 소스 코드나 이미지 내부에 하드코딩되어 있지 않고, HashiCorp Vault나 Kubernetes Secret으로 안전하게 주입되는가?
* [ ] **사내 네트워크 분리:** 온프레미스 Ollama 서버가 외부 인터넷망과 차단된 사내망(VPC 내부)에 위치하는가?
* [ ] **개인키/민감정보 마스킹:** 프롬프트 내 주민등록번호, 공장 도면 기밀 등의 패턴이 로깅 시스템에 평문으로 저장되지 않고 마스킹 처리되는가?
* [ ] **로그 파이프라인 연동:** Fluentbit 또는 Logstash를 통해 게이트웨이 접근 로그와 에러 로그가 사내 SIEM(통합보안관제시스템)으로 실시간 전송되는가?

### 3. 월 구독 유지보수 계약 체결 및 SLA(서비스 수준 협약) 가이드

구축 완료 후 안정적인 운영을 위해 체결하는 월 구독형 유지보수 서비스의 표준 가이드라인이다. 과장된 약속 대신 명확한 기술 지원 범위를 정의한다.

**SLA(서비스 수준 협약) 기준 예시:**

| 구분 | 서비스 등급 (Standard) | 서비스 등급 (Enterprise) |
| :--- | :--- | :--- |
| **대상** | 중견 제조·물류 기업 | 대기업 그룹사 |
| **지원 시간** | 평일 09:00 ~ 18:00 | 24시간 365일 (24/7) |
| **장애 대응 목표 (P1: 전면 중단)** | 2시간 이내 인지 및 착수 | 30분 이내 인지 및 착수 |
| **정기 점검** | 월 1회 원격 점검 | 월 1회 현장 방문 및 원격 점검 |
| **모델 업데이트 지원** | Llama 3 버전 업그레이드 지원 | Llama 3 및 신규 오픈소스 모델 커스텀 파인튜닝 지원 |

**구독 온보딩 프로세스 (계약 체결 후 2주간):**
1. **1주차 (인프라 이관 및 인수인계):** 사내 개발 리드 대상 게이트웨이 운영 매뉴얼 전달 및 관리자 세션 진행.
2. **2주차 (모니터링 튜닝):** Prometheus/Grafana 대시보드 연동 완료 및 장애 알림(Slack/Teams 웹훅) 실동 테스트 후 최종 승인.
