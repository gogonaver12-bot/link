## 6. 로깅, 모니터링 및 실시간 알림 시스템 구축

제조 및 물류 현장에서 LLM API는 이제 단순한 챗봇용이 아니라 생산 라인 이상 감지, 물류 최적화 경로 산정, 실시간 재고 예측 등 핵심 비즈니스 로직에 결합되어 있다. 따라서 장애 발생 시 즉각적인 인지와 자동 복구가 생명이다. 이번 장에서는 프록시 서버에 Prometheus 메트릭을 심고, Grafana로 시각화하며, Slack으로 실시간 경보를 보내는 구체적인 파이프라인을 구축한다.

### 1. Prometheus 및 Grafana 연동을 위한 메트릭 엔드포인트 생성

FastAPI 기반의 프록시 서버에 `prometheus-fastapi-instrumentator` 라이브러리를 적용하여 기본 HTTP 요청 수, 응답 지연 시간뿐만 아니라 **Anthropic API 호출 실패 횟수**와 **Ollama 폴백(Fallback) 전환 횟수**를 커스텀 메트릭으로 수집한다.

#### 구현 코드 (`metrics.py`)
```python
from prometheus_client import Counter, Histogram
from fastapi import Request
import time

# 커스텀 메트릭 정의
LLM_REQUEST_TOTAL = Counter(
    "llm_request_total",
    "Total LLM API requests",
    ["provider", "model", "status"] # provider: anthropic / ollama
)

LLM_LATENCY_SECONDS = Histogram(
    "llm_latency_seconds",
    "LLM API response latency",
    ["provider"]
)

CIRCUIT_BREAKER_STATE = Counter(
    "circuit_breaker_state_changes_total",
    "Number of times circuit breaker changed state",
    ["state"] # open / closed / half-open
)
```

#### 프록시 라우터 적용 예시 (`main.py`)
```python
from fastapi import FastAPI, Response
from prometheus_client import generate_latest, CONTENT_TYPE_LATEST
from metrics import LLM_REQUEST_TOTAL, LLM_LATENCY_SECONDS
import requests

app = FastAPI()

@app.post("/v1/chat/completions")
async def proxy_chat(request: Request):
    start_time = time.time()
    body = await request.json()
    
    try:
        # 1차 시도: Anthropic API 호출 (실패 가정 시뮬레이션)
        # response = call_anthropic(body)
        raise requests.exceptions.Timeout("Anthropic API Timeout")
        
    except Exception as e:
        # 폴백 발생 메트릭 기록
        LLM_REQUEST_TOTAL.labels(provider="anthropic", model="claude-3", status="fail").inc()
        
        # 2차 시도: Ollama (Llama 3) 폴백
        start_fallback = time.time()
        try:
            # response = call_ollama(body)
            LLM_REQUEST_TOTAL.labels(provider="ollama", model="llama3", status="success").inc()
            LLM_LATENCY_SECONDS.labels(provider="ollama").observe(time.time() - start_fallback)
            return {"source": "fallback_ollama", "result": "Llama 3 response"}
        except Exception as ollama_error:
            LLM_REQUEST_TOTAL.labels(provider="ollama", model="llama3", status="fail").inc()
            return Response(status_code=503, content="All LLM providers failed")

@app.get("/metrics")
async def metrics():
    return Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)
```

### 2. API 장애 발생 시 슬랙(Slack) 및 웹훅 실시간 알림 연동

장애가 발생하거나 서킷 브레이커가 열릴(Open) 때, 인프라 담당자가 즉시 인지할 수 있도록 슬랙 Incoming Webhook을 연동한다.

#### 슬랙 알림 모듈 (`alerter.py`)
```python
import requests
import os

SLACK_WEBHOOK_URL = os.getenv("SLACK_WEBHOOK_URL", "https://hooks.slack.com/services/YOUR/WEBHOOK/URL")

def send_slack_alert(title: str, message: str, level: str = "warning"):
    color = "#36a64f" if level == "info" else "#ff0000" if level == "error" else "#ffcc00"
    
    payload = {
        "attachments": [
            {
                "color": color,
                "title": f"[LLM Gateway Alert] {title}",
                "text": message,
                "fields": [
                    {"title": "Environment", "value": "Production-OnPremise", "short": True},
                    {"title": "Action", "value": "Fallback to Ollama(Llama 3) Activated", "short": True}
                ],
                "footer": "Manufacturing DX Infra Bot"
            }
        ]
    }
    
    try:
        response = requests.post(SLACK_WEBHOOK_URL, json=payload, timeout=5)
        response.raise_for_status()
    except Exception as e:
        print(f"Failed to send Slack alert: {e}")
```

### 3. 장애 복구 후 메인 API 자동 복귀 (Circuit Breaker Pattern)

무작정 폴백 상태로 머무는 것이 아니라, 서킷 브레이커 패턴을 적용해 메인 API(Anthropic)의 정상 여부를 주기적으로탐색(Half-Open)하고 자동으로 원복시킨다. 파이썬에서는 `pybreaker` 라이브러리를 활용한다.

#### 서킷 브레이커 적용 설정 (`circuit.py`)
```py
import pybreaker
from alerter import send_slack_alert
from metrics import CIRCUIT_BREAKER_STATE

# 3회 연속 실패 시 Open, 복구 시도(Half-Open)까지 60초 대기
db_breaker = pybreaker.CircuitBreaker(fail_max=3, reset_timeout=60)

@db_breaker
def call_anthropic_api(payload):
    # 실제 Anthropic API 호출 로직
    # 예외 발생 시 pybreaker가 실패 횟수 카운트
    pass

# 상태 변경 이벤트 리스너
class BreakerListener(pybreaker.CircuitBreakerListener):
    def state_change(self, cb, old_state, new_state):
        CIRCUIT_BREAKER_STATE.labels(state=new_state.name).inc()
        msg = f"Circuit breaker state changed from {old_state.name} to {new_state.name}."
        
        if new_state.name == "open":
            send_slack_alert("Anthropic API 장애 감지", msg, level="error")
        elif new_state.name == "closed":
            send_slack_alert("Anthropic API 자동 복구 완료", "메인 API 라우팅이 정상 복원되었습니다.", level="info")

db_breaker.add_listener(BreakerListener())
```
