## 1. 상세 설명 (문제 제기 및 해결)

### 🚨 [문제] 클라우드 LLM API 장애, 제조·물류 현장의 리스크
사내 업무 자동화, 물류 최적화, SCM(공급망 관리) 시스템에 Anthropic(Claude) API를 연동해 사용 중이신가요? 
클라우드 LLM 서비스에 예기치 않은 장애나 네트워크 지연이 발생할 경우, **현장의 실시간 물류 처리, 발주 승인, 고객 응대 프로세스가 즉시 마비**됩니다. 매뉴얼 전환이나 수동 대처만으로는 현대의 빠른 물류 속도를 따라갈 수 없습니다.

### 💡 [해결] Anthropic API 장애 시, Ollama(Llama 3)로 0초 자동 전환
본 가이드는 클라우드 API 장애 발생 시, 사내 온프레미스 서버에 구축된 **Ollama(Llama 3)로 실시간 자동 폴백(Fallback)되는 API 게이트웨이**를 직접 구축할 수 있는 실무 가이드 및 소스코드 패키지입니다. 
외부 클라우드가 멈추어도 내부 온프레미스 인프라가 즉시 이어받아 비즈니스 연속성을 보장합니다.

## 3. 자주 묻는 질문 (FAQ)

**Q1. 기존에 개발 중인 사내 시스템의 코드 수정이 많이 필요한가요?**
A. 아니오. 본 게이트웨이는 표준 API 규격을 준수하므로, 기존 애플리케이션에서 바라보는 엔드포인트(URL)만 게이트웨이 주소로 변경하면 되도록 설계되었습니다. 코드 수정량을 최소화했습니다.

**Q2. Ollama(Llama 3)가 Anthropic(Claude)의 성능을 온전히 대체할 수 있나요?**
A. Llama 3(예: 8B 또는 70B 모델)는 일반적인 요약, 분류, 단순 질의응답 영역에서 충분한 성능을 냅니다. 폴백의 목적은 '완전한 서비스 중단(Downtime) 방지'이므로, 핵심 비즈니스 로직이 멈추지 않도록 최소한의 방어선을 구축하는 데 초점이 맞춰져 있습니다.

**Q3. 온프레미스 서버 사양은 어느 정도가 필요한가요?**
A. Llama 3 구동을 위해 NVIDIA GPU(예: A10G, RTX 4090 또는 엔터프라이즈급 GPU)가 탑재된 온프레미스 서버 1대 이상을 권장합니다. 상세 사양은 구축 컨설팅 단계에서 환경에 맞춰 제안해 드립니다.

**Q4. GitHub 리포지토리는 어떻게 전달되나요?**
A. 스탠다드 컨설팅 계약 완료 후, 고객사의 담당 개발자 계정을 지정된 프라이빗 GitHub 리포지토리에 초대하여 즉시 클론(Clone) 및 활용하실 수 있도록 지원합니다.

**Q5. 유지보수 계약(월 50만 원)에는 어떤 지원이 포함되나요?**
A. Ollama 및 연동 모듈 버전 업데이트에 따른 호환성 점검, 게이트웨이 로그 분석을 통한 장애 원인 리포팅, 그리고 긴급 장애 발생 시 원격 기술 지원(월 2회 한정)이 포함됩니다.
